# خطيب — وكيل تحليل الخطابة

منصة تحلّل خطاب المتحدث (صوت أو فيديو) وتُصدر تقريراً تقويمياً داعماً، مبنية على n8n + OpenAI + Supabase، بواجهة محادثة عربية تعمل على Vercel.

## كيف يشتغل

1. المستخدم يفتح الصفحة ويجاوب على أسئلة قصيرة (الاسم، نوع الخطاب، الموضوع).
2. يختار: **تسجيل فيديو مباشر**، أو **تسجيل صوتي مباشر**، أو **رفع ملف جاهز**.
3. الطلب يمرّ عبر دالة Vercel (`/api/submit`) إلى وركفلو n8n.
4. n8n يفرّغ الصوت بـ Whisper، يحلّله بـ GPT-4o لفظياً، ثم يولّف تقريراً نهائياً داعماً مع بصمة أسلوبية.
5. التقرير يُحفظ في Supabase ويُعرض للمستخدم في نفس المحادثة.

**التسجيل نفسه لا يُحفظ في أي مكان** — فقط التقرير التحليلي.

## البنية

```
index.html              واجهة المحادثة (تسجيل مباشر + رفع ملفات)
api/submit.js           دالة Vercel: تمرّر الطلب إلى نموذج n8n
api/status.js           دالة Vercel: تمرّر استعلام حالة التنفيذ
supabase_schema.sql     جدول speech_reports
workflows/              نسخ احتياطية من وركفلوهات n8n
```

## ليش نحتاج دوال الـ API؟

المتصفح يمنع قراءة ردود الطلبات العابرة للنطاقات (CORS)، وخادم n8n ما يرسل ترويسات CORS. دوال Vercel تمرّر الطلب من نفس نطاق الصفحة، فينحل القيد بالكامل وتقدر الواجهة تعرض التقرير مباشرة.

## النشر على Vercel

1. من لوحة Vercel: **Add New → Project**
2. اختر مستودع `khatib-speech-agent`
3. Framework Preset: **Other** (بدون build command)
4. **Deploy**

ما فيه أي متغيرات بيئة مطلوبة — روابط النماذج مكتوبة داخل دوال الـ API.

## إعداد Supabase

شغّل محتوى `supabase_schema.sql` في **SQL Editor** داخل مشروع Supabase لإنشاء جدول `speech_reports`.

## قيود معروفة

- **تحليل لغة الجسد غير مفعّل حالياً.** المسار الحالي يعتمد على تفريغ الصوت بـ Whisper، فحقول لغة الجسد والتواصل البصري وحركة اليدين تُعاد بقيمة "غير متاح" بدل تخمينها. تفعيلها يحتاج نموذجاً يقرأ الفيديو بصرياً (مثل Gemini) في مسار منفصل.
- **البصمة الأسلوبية وصفية وليست بيومترية** — تصف أسلوب الإلقاء المميز، ولا تُستخدم للتحقق من هوية المتحدث.
- **يُفضّل ألا يتجاوز التسجيل 3 دقائق** لضمان استقرار المعالجة.
- التسجيل المباشر يحتاج اتصالاً آمناً (HTTPS)، وهذا متوفر تلقائياً على Vercel.
